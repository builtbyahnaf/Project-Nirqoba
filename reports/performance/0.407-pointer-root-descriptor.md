# 0.407-beta: static descriptor for one-word pointer roots

**Date:** 2026-11-11
**Change:** `root_layout` in `runtime/src/gc.cpp` returns one immutable,
process-lifetime descriptor for the ordinary single-pointer root shape.

## Shape and fast path

The shortcut applies only when all of these hold:

- no repeated elements (`repeated_count == 0`),
- object size `sizeof(void*)`,
- exactly one reference at offset zero,
- no trace callback (root layouts never supply one).

That shape is the one used by `nrq_gc_root_register`. Every other root shape,
including an 8-byte root with two references, keeps the existing four-entry memo
and interning path unchanged.

The descriptor is a namespace-scope `const nrq_object_layout`; its address is the
identity used by `add_slot_state` and `is_pointer_root`. In development builds
`root_layout` re-proves it with `layout_is_consistent` before returning it.

## Pool accounting

The descriptor is deliberately **not** in `layout_pool` and is **not pool-owned**.
It is excluded from `nrq_gc_layout_count`, `nrq_gc_layout_bytes`, and
`layout_bytes_total`; the last two describe pool-owned descriptors only. The
constant costs one process-lifetime object regardless of how many roots register
that shape.

## Tests

- `GcTest.PointerRootsBypassTheMemoAcrossMoreShapesThanItHolds`: six distinct
  record roots (more than the four memo entries) are interleaved with pointer
  roots; the pointer roots add zero memo lookups, and one still keeps a managed
  object alive through a collection.
- `GcTest.EightByteTwoReferenceRootDoesNotUseThePointerRootShortcut`: the
  degenerate 8-byte/two-reference shape takes exactly one memo lookup.
- `GcTest.PointerRootDescriptorIsNotPoolOwned`: registering eight pointer slots
  and a duplicate changes neither descriptor count nor layout bytes, and the
  duplicate registration agrees by descriptor identity.
- Clean build succeeded. Unit suite: **214/214**. Integration suite: **337/337**.

Method: `benchmarks/stress_test_2/run_benchmark.py --test 01|02|03 --impl nirqoba

## Caveats

- One process repeat per test (five measured rounds each), not the three-repeat
  protocol used for release reports. Host noise is visible: test 02's `BUILD_MS`
  changed even though this change does not touch tree construction.
- These are whole-program timings dominated by allocation, traversal and
  collection; the root-registration shortcut is a small part. The numbers show
  the change did not regress the workloads and that validation still holds, not
  a precise speedup.
