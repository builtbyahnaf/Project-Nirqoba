# Nirqoba — Pre-Migration Implementation Roadmap

**Project:** Project Nirqoba  
**Purpose:** Prepare the compiler and runtime for broader deterministic-ownership adoption  
**Strategy:** Incremental implementation, performance-first, no big-bang rewrite  
**Architecture:** Deterministic ownership by default; explicit borrowing and sharing; opt-in GC for cyclic/dynamic object graphs.

---

## Guiding rules

1. Preserve the existing hybrid memory model. GC is not being removed.
2. Reuse existing ownership, borrowing, cleanup, and allocator infrastructure. Do not rebuild completed functionality.
3. Owned values should have no reference-counting overhead.
4. Avoid runtime checks when correctness can be established statically.
5. Do not introduce abstraction layers that add indirection or allocation to hot paths.
6. Keep allocation, destruction, and ownership transfer predictable.
7. Benchmark before and after performance-sensitive changes.
8. Keep tests minimal but meaningful: one representative success case and one essential failure case per new semantic rule, plus existing regression suites.
9. Do not combine unrelated optimizations into one implementation stage.
10. Do not change public syntax or memory-model semantics without author approval.

## Phase 1 — Complete ownership inside aggregates

**Priority: Critical**

**Goal:** Make ownership-bearing fields behave like first-class owners rather than special cases.

### Implementation

- [x] Implement explicit ownership contracts for pointer fields in structs. `owned`,
  `borrow`, `borrow mut` and `shared` fields are implemented (`0.384-beta`,
  `0.389-beta`, `0.391-beta`).
- [x] Support owned and borrowed pointer fields. Borrowed fields in `0.384-beta`;
  `owned ptr T` fields in `0.389-beta` with transfer, move-only semantics and
  generated destruction; moved-field reinitialization and nested aggregate cleanup
  in `0.390-beta`; `shared ptr T` fields with retain-on-copy and
  release-on-destruction in `0.391-beta`; `uninit` partial initialization with
  destruction limited to initialized fields in `0.396-beta`, with whole-value and
  partial-overwrite guards in `0.397-beta`, nested
  completion propagation in `0.401-beta`, and resource-domain owned fields
  with per-domain destruction in `0.403-beta`.
- [x] Implement field-level move operations with source invalidation. (0.390-beta)
- [x] Implement safe field reinitialization after a move. (0.390-beta)
- [x] Extend recursive destruction to supported nested ownership-bearing aggregates.
  `aggregate.owned_drop` covers owned array, owned pointer, shared and
  resource-domain fields, in reverse declaration order (`0.389-beta`).
- [x] Implement correct partial initialization and partial destruction. (0.396-beta through 0.401-beta)
- [x] Support native-resource fields without allowing generic deallocation to destroy the wrong resource type. (0.403-beta)
- [x] Preserve existing whole-aggregate move behavior. (Unchanged; covered by the move/copy suites through 0.403-beta)

### Performance requirements

- No hidden heap allocation for ownership metadata.
- No per-field reference counting for uniquely owned fields.
- Destruction should be statically generated wherever possible.
- Avoid redundant null checks when the compiler already knows the field's ownership state.

**Completion:** Phase 1 is complete at `0.403-beta`. Aggregate ownership and destruction are deterministic, including field-level moves, reinitialization, partial initialization, nested destruction and all five resource domains.

## Phase 2 — Complete borrowing and lifetime propagation

**Priority: Critical**

**Goal:** Make borrowing useful across function boundaries without sacrificing predictable performance.

### Implementation

- [x] Extend lifetime propagation across function calls. Borrows record their
  originating owner and lexical depth; `&owner` aliases are tracked; borrowed
  arguments are revalidated through nested calls; outer-scope rebinding is
  rejected (`0.415-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Implement safe borrowed returns for supported source relationships.
  Borrowed returns name an explicit source parameter; direct, forwarded, and
  selected-source returns are checked against a live, unmoved owner, and the
  owner cannot be transferred to an owning parameter while the return is live
  (`0.419-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Support borrowing from aggregate fields.
  Borrows record the aggregate binding and dotted field path; direct and nested
  field borrows survive forwarding and borrowed returns, and replacing an
  overlapping field, moving the owner, or escaping its scope is rejected
  (`0.423-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Implement correct mutable-borrow exclusivity across nested calls.
  Overlapping mutable borrows and immutable accesses to the same owner or field
  path are rejected, argument order participates in exclusivity, forwarded
  returned borrows retain their path, and disjoint sibling fields remain
  independently borrowable (`0.427-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Preserve branch-selected borrow paths across conditional merges.
  Distinct possible field paths are retained and all are checked for overlap,
  while different owner allocations remain unusable (`0.431-beta`,
  `reports/pre-mmm/phase-02.md`).
- [x] Retain one-sided conditional borrows.
  A borrow live on only one path keeps its owner and field projection; every
  reachable overlapping access is rejected, disjoint fields stay available,
  and aliases, calls or returns that require a definite borrow are rejected
  (`0.437-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Refine conditional borrows after an explicit null check.
  A non-null guard turns a conditional borrow into a definite borrow only when
  the absent path is provably null; the proof is branch-local, preserves field
  paths, and is lost at joins without the same proof or on the null path
  (`0.441-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Follow short-circuit logical evaluation paths when refining null facts.
  `&&`, `||`, and logical negation retain only facts guaranteed on every path
  reaching the branch (`0.445-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Preserve branch-dependent borrow owner identities.
  Different owner allocations selected by branches are retained as compact
  secondary targets; every owner/path combination participates in conflict and
  liveness checks, while ambiguous aliases and calls remain rejected
  (`0.445-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Propagate borrowed-return effects through nested calls.
  The declared return source is cached in the function signature; nested and
  chained borrowed-return calls recover the original owner and field path, and
  overlapping results conflict while disjoint fields remain usable
  (`0.449-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Expire and reassign borrows along control flow.
  A borrow can be cleared with `nullptr` or replaced by another validated borrow;
  the old path is released, replacement owners must outlive the binding, and
  branch merges retain any borrow still possible on a continuing path
  (`0.449-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Summarize interprocedural borrow effects.
  Compact per-parameter read/write/alias/escape bits merge through nested and
  recursive calls, with conservative fallbacks for incomplete callees and no
  runtime tracking (`0.453-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Prevent borrow escape through aggregates and scope boundaries.
  Borrowed-field origins travel with aggregate values; inner-to-outer
  assignments, returns, calls, and aggregate-field storage are rejected while
  same-scope nested aggregates and disjoint field paths remain valid
  (`0.453-beta`, `reports/pre-mmm/phase-02.md`).
- [x] Audit write, alias, extraction, and branch-initialization boundaries.
  Immutable borrowed pointers and fields are read-only at dereference, index,
  compound, and address-taking boundaries; mutable field borrows require mutable
  storage; mutable aggregate borrow copies and conflicting in-aggregate aliases
  are rejected; branch-initialized aggregate state survives joins without
  leaking branch allocations (`0.457-beta`, `reports/pre-mmm/phase-02.md`).
- [ ] Add closure-capture ownership rules when closure support requires them.
- [ ] Prevent borrowed references from escaping their owner's lifetime.
- [ ] Implement the minimum escape analysis needed to reject invalid lifetime transfers.

### Performance requirements

- Borrowing must remain a compile-time concept wherever possible.
- Do not introduce runtime borrow counters or locks.
- Do not heap-allocate borrow descriptors for ordinary references.
- Preserve direct pointer access in optimized builds.

**Completion:** Common borrowing patterns work without runtime ownership overhead.

## Phase 3 — Make deterministic destruction complete

**Priority: Critical**

**Goal:** Ensure every supported control-flow path destroys owned resources exactly once.

### Implementation

- [x] Consolidate compiler-generated destruction into a predictable cleanup mechanism.
  Automatic ownership destruction and `defer` share one lexical cleanup stack;
  it is consumed innermost scope first and reverse declaration order within a
  scope (`0.461-beta`, `reports/pre-mmm/phase-03.md`).
- [x] Handle nested scopes and conditional initialization.
  Nested blocks release before their enclosing blocks. A branch-local defer or
  move keeps the automatic fallback for paths where it did not execute;
  uninitialized and moved aggregate fields are zeroed before typed destruction.
- [x] Handle early returns, loop exits, and moved values.
  Return runs every active scope down to the function root. `break` and
  `continue` release only the scopes they leave. `for` initializers have a loop
  cleanup scope released at the exit edge. Proven transfers remove dead
  automatic actions, and moving or returning an owner after `defer` captured it
  is rejected.
- [x] Ensure `defer` ordering is consistent with ownership destruction.
  Explicit defers run in reverse encounter order with automatic cleanups. A
  same-scope or unconditional defer supersedes the automatic action it replaces;
  conditional defers retain the outer fallback.
- [ ] Integrate cleanup with the language's future error/unwind model when that model is implemented.
  The error/unwind model does not exist yet. Its integration point is the active
  lexical cleanup stack: a future unwind edge must consume entries down to the
  handler scope depth in the same reverse order. No landing pads or unwind tables
  are generated today.
- [x] Ensure GC root frames close on every corresponding control-flow exit.
  Cleanup precedes each `return`, then the activation's root frame closes.
  Loop `break` and `continue` retain the activation frame because they do not
  leave the function; early-return and nested-loop counts are covered by
  regression tests.
- [x] Keep native-resource destruction separate from GC reclamation.
  File, socket, mutex, mapping, and secure resources use typed runtime
  destructors. Owned collector storage separately unregisters its GC root.

### Performance requirements

- [x] Generate cleanup only for values that actually require destruction.
  Trivial values and borrows have no cleanup entry. Transferred owners lose the
  dead automatic action instead of retaining a call on a null slot.
- [x] Eliminate redundant cleanup branches through compile-time ownership state.
  Unconditional transfers and same-scope/unconditional defers suppress the
  superseded action; conditional paths deliberately retain their fallback.
- [x] Avoid generic runtime destructor dispatch for statically known types.
  Each type lowers to its direct cleanup operation or recursive field walk.
- [x] Keep cleanup order deterministic.
  Reverse initialization/declaration order, with explicit defer ordering
  documented in `docs/memory/management.md`.

**Completion:** Every currently supported exit path has correct destruction semantics within the documented limitations. Error/unwind cleanup remains future work because the error model itself is not implemented.

## Phase 4 — Optimize the owned allocation path

**Priority: Critical**

**Goal:** Make deterministic ownership competitive at the runtime level.

### Implementation

- [x] Profile and optimize the ordinary owned allocation fast path. The global
  registry mutex and per-pointer node allocation were identified as the
  bottleneck, then removed from the process-default path (`0.465-beta`,
  `reports/pre-mmm/phase-04.md`).
- [x] Reduce allocator registry overhead on common allocation/deallocation
  operations. Ownership records are now inline in eight sharded open-addressed
  tables; the default path no longer allocates a hash node or takes
  `allocator_mutex`.
- [x] Reduce unnecessary synchronization in allocator operations. Shards lock
  independently; default allocations/releases skip the global allocator mutex
  and operation pin. Explicit per-allocation handles retain the pin on
  allocation and use the live ownership record on release (`0.469-beta`).
- [x] Improve small-allocation throughput. Allocation-heavy median fell from
  182.83M to 131.79M cycles (-27.9%) in the Phase 4 workload.
- [x] Improve bulk allocation and release. Twenty-thousand-block churn and
  cross-thread bulk ownership are covered by unit tests; destruction-heavy fell
  20.0% and mixed 19.2%.
- [x] Optimize allocator selection and ownership lookup. Pointer-sharded lookup
  and inline records replace one global map; reallocation moves records between
  shards.
- [x] Evaluate thread-local allocation caches only where measurements justify
  them. The existing 64-entry / 1,024-byte default cache is retained; the node
  and lock overhead around it was the measured cost, not the cache thresholds.
- [x] Ensure reallocations preserve ownership records without unnecessary
  metadata allocation. Reallocation now moves the inline record across shards
  without a registry node allocation.
- [x] Keep allocator-specific behavior isolated from ownership semantics. No
  ownership, move, cleanup, or exactly-once rule changed; the work is confined
  to the registry and default-allocation synchronization.

### Performance requirements

- Fast path should avoid global locks wherever safe.
- Avoid extra allocation for tracking a normal allocation.
- Keep metadata compact and cache-friendly.
- Preserve allocator identity and double-free protection.
- Never trade correctness for benchmark improvements.

**Completion:** Complete at `0.465-beta`. Two independent upgrades were measured
against `0.461-beta`: sharded lock-free-on-the-default-path lookup, then inline
open-addressed records. Allocation-heavy, destruction-heavy, and mixed workloads
improved 27.9%, 20.0%, and 19.2% by median; peak working set stayed flat within
16 KB. Exact checksums, 225 unit tests, 450 integration tests, cross-thread
stress, and the migration-scale Phase 3 programs pass. Report:
`reports/pre-mmm/phase-04.md`.

## Phase 5 — Establish the GC/ownership boundary

**Priority: High**

**Goal:** Make the two memory domains coexist cleanly.

### Implementation

- [x] Make ownership-domain transitions explicit in compiler lowering. Owned pointer storage with managed fields now registers a typed root on allocation, moves it on reallocation, and unregisters it before release or at frame end; shared storage uses a rooted allocation entry point (`0.469-beta`, `reports/pre-mmm/phase-05.md`).
- [x] Ensure owned containers holding managed references register and unregister roots correctly. Owned pointer storage and existing owned arrays publish typed roots only when their pointee/element has managed offsets; managed-field-free storage pays no GC tracking.
- [x] Ensure GC-managed objects never enter ordinary owned deallocation paths. Existing semantic negative tests reject `memory.deallocate` on managed, borrowed, shared, and resource values; Phase 5 adds no exception to that rule.
- [x] Ensure owned objects never accidentally acquire GC reclamation responsibility. Explicit storage keeps deterministic release; the collector only traces its managed fields while the root is live.
- [x] Preserve write barriers for managed-reference stores. Managed stores into owned and shared blocks continue through the existing barrier; frame-scoped roots use the established registration paths.
- [x] Optimize root registration and unregistration where profiling justifies it. Typed descriptors are shared per layout and only emitted when managed offsets exist; no measured need justified a new cache in this phase.
- [x] Ensure GC-managed references remain valid across supported allocation and collection points. New heap, stack, reallocation, cleanup-exit, and shared probes collect twice and read back `73`; managed call results and array roots retain their existing tests.
- [x] Keep cyclic object graphs in the GC domain rather than introducing unnecessary shared ownership cycles. Shared storage remains explicit reference counting; collector cycle handling is unchanged and covered by the existing GC suite.

### Performance requirements

- Ordinary owned allocations must not pay GC tracking costs.
- GC root operations must not add overhead to unrelated owned values.
- Avoid unnecessary cross-domain conversions.
- Keep GC metadata and ownership metadata separate.

**Completion:** Complete at `0.469-beta` for the supported boundary. Typed roots keep managed fields in owned and shared storage visible until deterministic release; roots are removed before release or at frame end. 228 unit tests and 455 integration tests pass, including `owned_pointer_gc_roots`, `stack_owned_pointer_gc_roots`, `owned_pointer_gc_reallocation`, `owned_pointer_cleanup_gc_roots`, and `shared_pointer_gc_roots`. The explicit allocator-handle release path also dropped its redundant pin: 1/2/4-worker medians improved 21.0%/27.1%/46.3%. A pre-existing compiler crash for aggregate fields declared as `shared ptr T`/`owned ptr T` when `T` contains managed fields remains a documented limitation. Report: `reports/pre-mmm/phase-05.md`.

## Phase 6 — Compiler lowering and optimization integration

**Priority: High**

**Goal:** Make ownership semantics disappear into efficient machine code wherever possible.

### Implementation

- [x] Verify ownership attributes survive TIR and MLIR lowering. Existing `nirqoba.ownership`, `owned`, `borrowed`, `shared`, `noalias`, `readonly`, and `nocapture` tests pass; `owned_pointer_root_elision_ir` checks the GC side at `-O2`.
- [x] Eliminate redundant ownership-state operations. Stack-owned storage with no collection point no longer publishes a typed root or executes a write barrier (`0.473-beta`, `reports/pre-mmm/phase-06.md`).
- [x] Remove unnecessary cleanup calls after statically proven moves. Existing move/cleanup tests, including transfer and early-return cases, pass unchanged; Phase 6 added no cleanup that could duplicate destruction.
- [x] Optimize known-size allocation and destruction. Stack placement and native cleanup remain intact; the root/barrier elision lets LLVM promote private owned blocks instead of preserving calls around them.
- [x] Improve scalar replacement for ownership-bearing aggregates where safe. The Phase 6 benchmark shows the root/barrier elision exposes owned stack blocks to SROA (runtime 104.13 ms -> 16.63 ms).
- [x] Ensure alias and lifetime information reaches LLVM optimization passes. Existing alias/attribute IR tests pass; parameter and result `noalias`, immutable `readonly`, and non-escaping `nocapture` are unchanged.
- [x] Avoid unnecessary pointer loads, stores, and temporary descriptors. The elision path emits a plain store instead of `nrq_gc_root_store` and no typed-root call or descriptor when no collection point exists.
- [x] Preserve correct GC root and write-barrier behavior through optimization. Shared-field roots and observable stack roots pass at `-O0` and `-O2`; only unobservable activations elide bookkeeping.

### Performance requirements

- Ownership should not introduce overhead when its guarantees can be resolved statically.
- Avoid redundant runtime ownership checks.
- Do not add optimization passes without evidence that they improve generated code.

**Completion:** Complete at `0.473-beta` for the supported lowering and optimization surface. The Phase 5 nested shared-field crash is fixed; unobservable stack-owned roots and barriers are elided; 228 unit tests and 460 integration tests pass. Benchmark: runtime -84.0%, compile time -14.2%, peak compiler RSS -3.7%, executable size -4.3% on the isolated root-elision workload. Report: `reports/pre-mmm/phase-06.md`. Conservative restrictions and the missing sanitizer run are documented there.

## Phase 7 — Migrate existing subsystems incrementally

**Priority: High**

**Goal:** Expand deterministic ownership adoption without destabilizing the language.

### Implementation order

1. Compiler-owned temporary resources.
2. Runtime-owned buffers and internal allocations.
3. File, mapping, mutex, and other native-resource handling.
4. Container and aggregate internals.
5. Asynchronous/task resources when the concurrency runtime is implemented.
6. Future tensor and device-buffer ownership.

For each subsystem:

- [ ] Move its internal resource management onto the established ownership path.
- [ ] Preserve existing external behavior.
- [ ] Remove obsolete internal GC dependencies only when no longer needed.
- [ ] Benchmark the migrated subsystem.
- [ ] Keep a rollback point until the new implementation is stable.

### Compiler-owned temporary resources — roadmap 1

Completed at `0.477-beta`, retained through `0.483-beta` (`reports/pre-mmm/phase-07.md`):

- [x] Move compiler-generated artifacts onto the deterministic ownership path. Build objects and executables are staged through move-only `TemporaryArtifact` leases and published only after success; `run` removes its executable and object unless `--keep-artifacts` is given.
- [x] Preserve external build behavior. A successful `build` still produces the same object and executable paths; the `hello` executable is byte-identical to `0.473-beta`.
- [x] Remove obsolete internal GC dependencies only when no longer needed. None existed on this path; the compiler is a native process and its artifacts now use C++ RAII, not tracing.
- [x] Benchmark the migrated subsystem. 41 interleaved samples: build +3.51%, run -0.88%, `new` +7.05%, peak RSS +0.24%; `run` artifacts fall from 2 files / 10,300 B to zero.
- [x] Keep a rollback point. Commit `ae26bc1` is the `0.473-beta` baseline; it was checked out as a disposable worktree for measurement and removed after verification. `--keep-artifacts` restores the old `run` artifact behavior.
- [x] Publish project scaffolds atomically. `TemporaryDirectory` writes the complete tree beside the target and renames it into place; failures leave no partial project.

### Runtime-owned buffers and internal allocations — roadmap 2

Completed at `0.483-beta`, contract revised at `0.495-beta` (`reports/pre-mmm/phase-07-part-3.md`):

- [x] Move its internal resource management onto the established ownership path. The process argument descriptor is static storage; `file.read_text` uses a process-owned arena.
- [x] Preserve existing external behavior. Repeated reads return the same bytes and length; string values are immutable after the call.
- [x] Remove obsolete internal GC dependencies only when no longer needed. None existed on this path; the runtime owns the arena directly.
- [x] Benchmark the migrated subsystem. Part 3 rerun: 20,000 reads +0.12% wall and +1.10% peak RSS, neutral within noise.
- [x] Keep a rollback point. `30a6ae6` and `70126a6` were built as disposable worktrees for measurement.
- [x] Define a sound string lifetime. Because `string` is a raw borrowed pointer with no release point, read strings are valid for the whole process, including deferred cleanup and static destructors; the OS reclaims them at termination. Entry-return invalidation was removed.

### File, mapping, mutex and other native resources — roadmap 3

Completed at `0.483-beta`, extended at `0.495-beta` (`reports/pre-mmm/phase-07-part-3.md`):

- [x] Move its internal resource management onto the established ownership path. Live file, mapping and mutex registries are cleared and their OS handles released at shutdown; explicit close remains the normal path.
- [x] Preserve existing external behavior. Handle operations, mapping sizes and mutex semantics are unchanged; stale tokens are rejected after close or shutdown.
- [x] Remove obsolete internal GC dependencies only when no longer needed. These registries never depended on the collector.
- [x] Benchmark the migrated subsystem. File open/close -2.04%; mutex create/destroy -10.71% after the slot-table migration.
- [x] Keep a rollback point. The `0.477-beta` and `0.483-beta` worktrees covered these comparisons.
- [x] Replace per-open map nodes. File and mutex handles use generation-checked inline slot tables.
- [x] Complete termination cleanup. `system.exit` retires uncontended registries with try-lock; busy registries are reclaimed by the OS instead of blocking termination.
- [x] Use a rollback transaction for paired outputs. Object and executable are published with hard-link backups and restored together on failure.

### Container and aggregate internals — roadmap 4

Partially complete at `0.495-beta` (`reports/pre-mmm/phase-07-part-3.md`):

- [x] Migrate shared aggregate root metadata. Up to eight managed-reference offsets are inline; deeper layouts retain the vector fallback.
- [x] Remove per-drop aggregate path allocations. Owned-drop and shared-retain traversal uses `SmallVector<int64_t, 8>`.
- [x] Preserve aggregate destruction and alias behavior. Existing owned-aggregate, shared-field and cleanup cases pass unchanged.
- [x] Benchmark or account for the change. No separate container allocator exists; the allocation removal is structural and covered by aggregate tests, not a claimed speedup.
- [ ] Complete a container-internals audit. Owned arrays, views and SoA already use deterministic ownership/GC roots; no redesign was attempted.

Remaining Phase 7 work is the container-internals audit in roadmap 4. Async/task
resources (roadmap 5) and tensor/device buffers (roadmap 6) have no subsystem in
this tree, so they are not applicable. Collector pages and allocator shards remain
outside this phase.

**Completion:** Partially complete at `0.495-beta`: roadmap steps 1–3 are
migrated, aggregate internals are migrated, and the container audit remains.
Steps 5–6 have no implementation to migrate.

## Phase 8 — Migration readiness and default-policy transition

**Priority: Critical**

**Goal:** Expand deterministic ownership to the supported language surface.

### Implementation

- [ ] Enable deterministic ownership by default for every completed supported type and operation.
- [ ] Keep unsupported ownership patterns explicitly rejected rather than silently falling back.
- [ ] Keep GC opt-in and available for supported cyclic/dynamic object graphs.
- [ ] Remove obsolete legacy paths only after their replacements are proven.
- [ ] Update language documentation and examples to reflect actual behavior.
- [ ] Publish migration notes for users.
- [ ] Run the full regression suite and representative performance suite.

**Completion:** The supported language surface consistently follows the intended hybrid memory model.

---

## Minimal validation policy

Do not build a massive test matrix for every small change.

For each new ownership rule, prioritize:

1. One positive test proving the intended operation works.
2. One negative test proving an invalid operation is rejected.
3. One regression test if the change touches existing destruction, borrowing, or GC behavior.

Run the existing full suite at phase boundaries and before merging substantial changes.

Performance changes require benchmark evidence, not more unit tests.

---

## Explicitly out of scope for this roadmap

- Removing the garbage collector.
- Replacing the entire allocator architecture.
- Implementing a fully concurrent or parallel garbage collector.
- Rewriting the compiler's ownership system from scratch.
- Introducing runtime borrow checking.
- Implementing tensor/GPU runtime support prematurely.
- Adding new public syntax without an approved design.
- Unrelated SIMD, threading, or language-feature work.

---

## Final migration gate

The migration is ready to expand when:

- [ ] Supported aggregate ownership is complete.
- [ ] Common borrowing and lifetime propagation work.
- [ ] Deterministic cleanup covers supported control flow.
- [ ] Owned allocation fast paths are stable and benchmarked.
- [ ] GC/ownership boundaries are correct.
- [ ] Compiler optimizations preserve ownership semantics.
- [ ] At least the first major runtime/compiler subsystems have migrated successfully.
- [ ] Performance has not regressed materially against the baseline.

**Final principle:** Nirqoba should not become faster by making ownership more complicated. It should become faster because ownership gives the compiler enough information to remove work.
